# .claude/tests

Gameplay-driving test suites that are worth keeping.

Most games in this repo are verified by a drive suite written in the session
scratchpad and thrown away afterwards — that is still the default, and it is
fine for a game whose rules fit in your head. A suite earns a place here when
**re-deriving it would cost more than reading it**: when it encodes fairness or
design invariants rather than just poking the UI.

| Suite | Game | Why it lives here |
| --- | --- | --- |
| `drive-wayfinder.cjs` | `games/wayfinder/` | 82 checks including a BFS walkability gate, a final-leg gate (every route the lessons instruct is walkable), and a cheat gate (each lesson refuses to complete without its technique). These caught an objective placed behind a 74° face and another placed inside a stream channel. |
| `drive-grid-defense.cjs` | `games/grid-defense/` | 50 checks on RULES (balance lives in the eval next to it, so a rebalance never fights a mechanics regression): the wave-by-wave intro schedule, the timer-driven continuous flow (grace → wave → gap → level clear, ten waves to a level, nothing waiting on a tap), level retry with a whole-attempt rollback so a level cannot be farmed for cores by dying on purpose, tree gating, persistence, scoreboard, and the curve's shape. It also presses the canvas-drawn UI through real touch events, which is where this repo's stale-hitbox bug lives. Caught a clear-phase that re-fired and farmed the level bonus forever, a between-levels auto-save that reopened the next level holding the previous level's board, random elite stamping that made wave HP dip level-to-level, and a deferred game-over screen that popped over a freshly started run. |
| `eval-grid-defense.cjs` | `games/grid-defense/` | Balance and pacing, not rules. Plays the real campaign with declarative strategy personas — no skills, bad skills, bad tower mix, bad placement, no armory, and **one per skill tree** — and asserts the design's difficulty *claims*, including the hard requirement that **specialising in any single tree can still clear all ten levels**. Seeded (`--seed`) because crit rolls alone swung a verdict by two levels between identical runs. It caught: difficulty running backwards inside a level, research strictly dominating the armory, a 23-strategy agent exploration whose headline "3.3x gap" was really short skill lists stranding 88 of 116 points, and two trees that could not finish alone (ENGINEERING after deploy caps gutted its economy identity, COMMAND for having no way to turn army size into damage). |
| `drive-turret-builder.cjs` | `games/turret-builder/` | 207 checks on RULES. The headline is the CD's own worked example — ELEC+BLAST+FIRE+ICE, one per side — asserted **to the decimal off a damage ledger** (`__TB.setLog`) fired at pinned dummies with known armour and resist: 12.5 kinetic and 9.375 burn on the main target, 6.25 and 4.6875 on the arc target, 1.25 and 0.9375 on a bystander, full chill on all three. Then each module alone and stacked four deep, the damage-decays/effects-don't split, continuous tracking and instant snap, all four diagonal boosters (including the CD's claim that two BLAST plus a TWIN transfers a full 100%), all fifteen named combos with their effects and their rotation-invariance, the persistent discoveries codex, walls, economy, flow, the sawtooth, and the canvas UI pressed through real touch events. All **five graphics styles** too — TOON is the default for a first-time visitor, the dropdown ticks the current one, the pick survives a reload, and each renderer is driven through REAL frames on a populated board, because a per-style throw inside `draw()` ends the rAF chain and freezes the game. That set discriminates: breaking `drawGroundNeon` fails only the NEON check. Two more checks guard the skin system itself. One fingerprints each cel skin's turret **silhouette** and requires every pair to differ by at least 3% of samples — written that way because "all four hashes are distinct" passed with `turret: drawTurretMech` deliberately unregistered (the palette still went through), and a silhouette hash alone then passed on a **one-sample** antialiasing difference; the closest honest pair is 7.9% and a fallen-through skin is 0.1%. The other paints one **disc** through `celShape()` inside a rotated frame (`paintCelProbe`), because the turret-tracking sun measurement only bites on a skin that swings a large lit body — STEAMPUNK's thin cannon and STONE AGE's thin arm both pass a ring through geometry that never rotates — and a disc is rotation-invariant, so its bright bearing can only move if the light does. Then a **road group**, all of it measured off pixels: the road's walk order is a one-cell chain with no repeats, its two ends are exactly the cells `canPlace('wall', …)` refuses, every road-cell boundary is struck darker than the cell centre (the CD's "align the lines with the grid so I can see where a wall goes", stated as a measurement — the joints used to be spaced along the path and permanently out of phase), both end cells carry an arrow the plain road does not, and every buildable cell is green at five sample points in every cel style (five, not one: a dirt verge hugging the road misses every cell CENTRE while browning the quarter of each neighbour nearest it, and the first version of that check stayed green against exactly the thing it was written to catch). And the one that makes "a skin is paint" an assertion rather than a claim: the identical deterministic scenario — three module-ringed turrets, a wall, 26 seconds of a live wave — played out under **all five styles with real frames drawn between ticks**, requiring every gameplay number (creep distance, HP, chill, turret aim to six places, wall HP, cash, lives, links) to come out byte-identical. Drawing between the ticks is the whole point: a check that only stepped the sim could not see a draw function writing to a creep, caching onto a tile, or moving the board geometry, which is the failure a large skin system actually invites. It discriminates — `c.d += 0.001` inside `drawCreepMech` fails it and names MECH. Its own first version failed on four styles for a reason that had nothing to do with skins: it put the tracked creep's **id** in the snapshot, and `creepSeq` is a page-lifetime counter no run reset touches, so later styles number their creeps higher. Every one of those six was verified by breaking it. All of them first failed for the same wrong reason — they were reading a `LEVEL 1 · SUBSTATION` toast painted over the board — which is why `clearToasts()` exists. And the **placement rules** — a module must touch a turret or wall, a booster a turret diagonal, wall-only ARMOR/REGEN a wall — with the overlay's mask asserted as the same set `place()` accepts, every cell classified exactly once, and the overlay driven through real frames for every kind and mid-drag. That group discriminates too: reverting `canPlace` to the old anything-anywhere rule fails 11 checks and leaves the mask-consistency ones green, which is right — they assert coherence, not the rule. One check measures **pixels**: the cel rim-light must stay fixed in screen space while a turret rotates to track, sampled as the bearing of the brightest pixel on a ring inside the hull across five aim angles (stubbing `frameRot()` to 0 takes the spread from 0° to 90° — it caught a live defect on 2026-08-23 that no amount of looking at the game had). Caught a booster link crashing the turret bloom (`l.from.mod` is undefined for a booster), a codex that diverged from disk after a storage wipe, and dummies with no speed that silently made every wall test vacuous. |
| `eval-turret-builder.cjs` | `games/turret-builder/` | Balance and pacing, not rules. 22 claims, played with declarative personas — bare turrets, a player who keeps trying to orphan modules (the board now refuses every one, so the persona ends a campaign having wired nothing — the placement rule measured end-to-end rather than in a unit check), a grid that refuses to share, all-in on each of the five modules, boards built entirely of named combos, no boosters, no walls, no lab, exit-camping. It asserts the CD's two design principles directly: **all-in on a damage type carries a run** (increasing returns) and **a combo board is competitive with the best stacked board** — while also pinning the honest counterparts, that **all-ICE cannot carry a run** (a multiplier with nothing to multiply) and **not every combo is good** (CRYO SHELL chills beautifully and kills slowly). It produced the findings that shaped both passes: bare gray triangles reached level 6 until armour was made to scale with the campaign floor; the useful `HP_LEVEL` band after the payload redesign is only ~10% wide (1.30 clears, 1.40 stalls the reference build at 5); and chill measurably stretches a level to ~11 minutes, which is capped so it cannot get worse. Also the meta-lesson: for an hour *no value of `HP_LEVEL` changed any outcome*, because the persona settled for the cheapest affordable lab tier instead of saving for its priority. **If a curve sweep does nothing, the curve is not what is stopping the persona.** |
| `drive-neon-clash.cjs` | `games/neon-clash/` | 67 checks on the rules and the four design promises that are easiest to break silently. The first is **the bunker protects its garrison**: an enemy parked against it must chew the *building* while the occupants' HP never moves, a garrisoned melee unit must fire past its own 6-unit reach through the slits, and when the bunker dies both occupants must come out **alive and mobile** — turning that into a coffin would still pass every other check in the file. The second is the **rotated two-player tray**: two touch identifiers, one starting in each tray, dragged and released together, must deploy one unit per side and charge each side only for its own card, while the same top-tray drag in vs-AI mode must do nothing at all. Around those: the deploy contract from both sides (own half only, pay or fail, a refused deploy costs nothing, a drop on the halfway line clamps inward), the bunker and garrison caps, the stat *shape* the design asks for (tank walls, fighter rushes, archer reaches) rather than its exact numbers, energy at 1/sec capped at 20 and doubled in sudden death, a razed base ending the match, that the AI plays cards without ever spending energy it does not have, and the **portrait lock** — a landscape viewport must keep the portrait layout, and a touch whose screen coordinates are pushed through the view transform must still hit the card it visually covers, which is the check that fails the moment a pointer handler reads `getBoundingClientRect().left` instead of un-rotating. The third promise is **fireball is a comeback card, not a win condition**: its damage must measure 90 dead centre and exactly 45 at the rim (the falloff *is* the balance — flatten it and the card stops rewarding you for reading a crowd), it must leave anything outside the circle untouched, never hurt your own units, never scratch **either** base, and never reach a garrison through the bunker sheltering it; the knockback must actually shove a unit backwards against its own march, a spell dropped on your own bunker must cast rather than garrison, a unit must still land `DRAG_OFF` ahead of the finger while a spell lands exactly under it, and LEGEND must answer a massed push with a cast of its own — the check that proves the AI reaches the spell through the same `tryDeploy` the player uses. The fourth is the **siege lock** — a unit that has landed a blow on a building commits to it until it falls — and it is pinned from *both* directions, because only one of them is the interesting failure: a committed attacker must ignore a defender that walks up beside it (and keep chewing the building meanwhile), while a unit merely *marching* at a base, which has committed to nothing, must still divert onto that defender. Collapsing those two into one rule in either direction reads as a working game and quietly deletes the counterplay the lock exists to create; a third check kills the besieged bunker and requires every attacker it held to be released and re-target. |
| `drive-phasic.cjs` | `games/phasic/` | 246 checks: scripted player solutions for all 24 authored curriculum levels, solver-script replays for every generated level below 65 plus endless spot checks (a served level is a solved level), template-coverage and in-path weave gates (void under the pour line, mid-field hedge, ridden fan lane), base-state rules (born-liquid needs a latched frost; removing it melts again), obstacle gates (void consumes + retry, bush stops stone/drinks liquid/passes vapor, fan blows only gas), the Stopper tactic both ways, symmetric reversion, live sockets, win-with-deployed-well, STUCK, menu format, and a complexity-ramp assertion. Earlier rounds caught freeze teleporting a puddle mid-air, liquid too flat to refreeze (missing cohesion), gas unable to find a flue (missing pressure guidance), and a stale home flag on melted gems that could have faked a win. |
| `drive-star-surge.cjs` | `games/star-surge/` | 61 checks pinning the two-axis weapon model (permanent XP tier = quality; in-run pip 1-4 = quantity/area, **never** fire rate): every weapon's `weaponCooldown()` is pip-invariant; blaster/missiles/bolas fire exactly `[1,2,3,4]` projectiles across pip; bombs alternate turret-count and blast-radius (`BOMB_UPGRADES`); beam/flame band/lobe counts track pip 1:1; chain hits exactly `[1,3,5,7]` enemies (zero jumps at pip 1, +2/pip); EMP radius grows with pip while damage doesn't; each missile tier's effective turn rate implies exactly its `MISSILE_MIN_TURN_RADIUS[tier]` floor; enemy hp and incoming ship damage both rise with `campaignDifficulty()`; plus a crash-free smoke pass per weapon. Seven more cover the ⚙ graphics-style setting: cel/toon is the default with nothing stored, the dropdown offers exactly the two known styles, the pick updates the live renderer *and* persists, the cog sits clear of ← and 🔊 and its panel closes on the first canvas touch, and — the two that actually earn their place — **both styles paint a frame holding all four enemy types, both boss kinds, every projectile shape and a shielded ship at once** (a per-style render branch that only throws on one enemy type is invisible until that wave arrives), and **cel shading keeps the sun fixed in screen space while a sprite spins**, measured by walking a ring inside the spinner’s dome and asserting the brightest bearing does not move with `e.ang`. That one discriminates: stubbing `frameRot()` to 0 takes the spread from 0° to ~170°, which is exactly the "sprite drags its own shadow round" tell that no other check would notice. Written after this exact model was violated once (a pip-based fire-rate bonus that fought the tap-fast-vs-hold-steady player-skill mechanic, reverted the same session) and the missile floor was added to close a "fill the screen with missiles" exploit — see `.claude/star-surge.md`'s Lessons learned for both. Nineteen more cover the **sector report → launch → allied station** loop added 2026-08-23. The ones that earn their place are the structural invariants, not the pixels: **COMBAT resumes the SAME run** (score, XP, salvage, weapon pip and hull all carry through the station — a future refactor reaching for `startGame()` here would silently zero a player's score mid-campaign and no other check would notice); **the two currencies stay unconvertible** (repair debits credits and never XP, shipyard unlocks debit XP and never credits); **every callout points at a feature on its own side of the station**, which is the single property that keeps the four connector lines from crossing the station or each other, and which no screenshot review will catch once someone re-pairs a button; **a skin is paint** — the station layout signature is identical under both graphics styles; and **the shipyard returns to the station with no second crossfade** (a replayed veil also swallows taps, so a returning player finds a dead screen — this shipped broken and was caught by driving the flow, not by reading it). All three of the visual/structural checks were negative-controlled: making the layout skin-dependent, re-pairing REST to a right-hand feature, and letting the neon skin fall through and paint nothing each fail exactly the intended check and nothing else — the fallen-through skin scores 8 lit samples against an honest 2023, so the bar at 300 is nowhere near vacuous. (Redo one with `.claude/scripts/negtest.sh save/restore` — these predate it and were restored by hand.) Six more pin the **routing** after the menu screen was removed: the game opens on pilot select and a pilot goes straight to its station (asserting `typeof showMenu === 'undefined'`, so a reintroduced menu fails loudly rather than stranding the player on a screen nothing returns to); REST banks a run and re-picking the pilot resumes score, hull, pip, shields and banked totals exactly; dying clears the run so the next pick starts fresh at the checkpoint; the death screen offers RETRY and PILOTS and no route to a menu; and **the stage banner stops painting off the play screen** — `stageBanner` only ticks down inside update()'s play branch, so off-play it freezes and keeps painting, which is how "STAGE 1 · WAVE 1" ended up sitting behind the SHIP DOWN overlay. The last two were negative-controlled through `negtest.sh`: removing the banner guard and making `restoreRun()` ignore the banked run each fail exactly their own check (banner: 563 gold pixels in the band either way when broken, 0 off-play when fixed). Uses `page.evaluate` calls into the game's own module-level globals/functions directly (no `window.__GD`-style debug handle exists here). |

Run them the same way as the smoke gate:

```
npm install playwright-core          # once, any directory
NODE_PATH=<that dir>/node_modules node .claude/tests/drive-wayfinder.cjs
```

Each prints a `... DRIVE: N passed, M failed` final line and exits 0/1.
